# 智能体范式

## ReAct 模式
ReAct 模式是一种智能体范式, 它通过循环执行三个步骤来完成任务:
1. Thought (思考)
2. Action (行动)
3. Observation (观察)

### 主要特点
- 高可解释性. 透明. 通过 Thought链 可以看到智能体每一步的思考过程.
- 动态规划与纠错能力. 每一步都根据从外部获取的 Observation 来动态调整后续的 Thought 和 Action.
- 工具协同能力. 将LLM的推理能力与外部工具的执行能力相结合, 突破了 LLM的 知识时效性与计算准确性等固有局限.

### 固有局限
- 对LLM自身能力的强依赖. 高度依赖底层LLM的综合能力. 如果LLM的能力不足, 会在 Thought环节产生错误的规划; 或者在 Action环节生成不符合格式的指令.
- 执行效率问题. 由于其循序渐进的特性, 完成一个任务通常需要多次调用LLM, 每次调用都伴随网络延迟和计算成本.
- 提示词的脆弱性. 整个机制的稳定运行建立在精心设计的提示词模版上. 模版中的微小改动, 或用词差异, 都可能影响 LLM的行为.
- 可能陷入局部最优. 缺乏一个全局的长远规划, 可能因为眼前的 Observation 而选择 看似正确但长远上并非最优解的路径, 甚至可能陷入"原地打转"的无限循环中.



## Plan-and-Solve 模式
这种范式将任务处理分为两个阶段:
1. 计划阶段
2. 解决阶段

### 适用场景
尤其适合结构性强, 可以清晰分解的复杂任务.
- 多步数学应用题. 需要先列出计算步骤, 再逐一求解.
- 需要整合多个信息源的任务(报告撰写).
- 代码生成任务. 需要先构思好函数/类/模块的结构, 再逐一实现.



## Reflection
为智能体引入一种事后(post-hoc)的自我校正循环, 使其能像人类一样, 审视自己的工作, 发现不足, 并进行迭代改进.

### 核心流程
三步循环:
1. 执行. 使用熟悉的方法(ReAct 或 Plan-and-Solve)来完成任务, 生成初步方案或行动轨迹. 看做 "初稿".
2. 反思. 启动一个独立的LLM, 来扮演"评审员", 对初稿进行多维度审查:
   - 事实性错误. 是否存在于常识或已知事实相悖的内容?
   - 逻辑漏洞. 推理过程是否存在不连贯或矛盾?
   - 效率问题. 是否存在更高效的解决方案?
   - 遗漏信息. 是否忽略了问题的某些关键约束或方面?
3. 优化. 将初稿和反馈 作为新上下文, 要求LLM根据反馈内容, 对初稿进行修改或补充.

### 劣势
1. 模型调用开销增加. 每一轮至少需要额外调用两次LLM (一次反思, 一次优化).
2. 任务延迟提高. Reflection 是串行过程, 要先完成执行, 再进行反思, 再优化.
3. 提示词复杂度增加. Reflection 的成功高度依赖于高质量, 有针对性的提示词.

### 优势
1. 解决方案质量的跃迁. 能将合格的初始方案, 优化成优秀的最终方案.
2. 鲁棒性与可靠性增强. 通过自我纠错, 能够避免或减少错误的执行路径, 提高智能体的可靠性和稳定性.


### 适用场景
Reflection 是一种以成本换质量的策略. 适合对最终结果的质量和准确性及可靠性要求较高, 但对任务完成实时性要求较低的任务.
- 生成关键的业务代码或技术报告.
- 科学研究中的复杂的逻辑推演.
- 需要深度分析和规划的决策支持系统.
