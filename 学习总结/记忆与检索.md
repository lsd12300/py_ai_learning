# 一、动机：为什么需要记忆与 RAG
两文共识：LLM 本质无状态 + 知识静态有限。
- **无状态**：每次调用独立，导致上下文丢失、个性化缺失、无法从经验学习、多轮前后矛盾。同一进程内暂存历史只是临时列表，不跨会话持久化。
- **知识静态**：训练数据有截止日期、领域深度不足、易幻觉、无来源可解释。
- **解决**：记忆系统（跨会话持久化）+ RAG（外部知识库注入）。


# 二、记忆分类（认知科学框架，取并集）
两文同源 Atkinson & Shiffrin 认知模型，分类互补：
| 层次 | 认知对应 | Agent 对应 |
| --- | --- | --- |
| 工作记忆 | 15–30秒，7±2项 | 上下文窗口/当前会话；ch3 细分出轨迹（append-only 完整事件记录）vs 工作记忆（按相关性筛选的动态子集）|
| 语义记忆 | 一般知识概念 | 提炼出的稳定事实（偏好、规则、知识点）|
| 程序记忆（ch3） |	技能流程 | 行为模式：如订机票的标准流程；2026年行业已收敛为三大长期记忆之一（ch3 更贴合主流）|
| 感知记忆（ch8） |	多模态感知 | 图像/音频，跨模态检索（ch3 另论多模态信息提取，两处一致）|
三套正交分类体系（ch3）：存在哪里（轨迹/长期记忆/业务状态）×怎么存（四种格式）×存什么（情景/语义/程序）。


# 三、记忆生命周期
两文流程一致：编码 → 存储 → 检索 → 整合（consolidate）→ 遗忘。
- **编码/存储**：LLM 从对话提取候选记忆，带选择性（只留有用事实）、抽象化（提炼通用偏好）、结构化（标记类型：偏好/限制/账号）与重要性评分（0–1）。
- **整合**：工作记忆 → 情景记忆 → 语义记忆的逐级固化（ch8 默认重要性>0.7 升级）。
- **遗忘**：ch8 三策略——基于重要性、基于时间、基于容量；ch3 更细的评分体系——访问频率、时间衰减、情感强度、信息独特性四因子，辅以聚类压缩（相似记忆生成代表摘要）、抽象泛化（情景→语义）与版本化冲突处理（保留历史版本、标记最新）。两者合并即完整遗忘机制。


# 四、记忆存储表示（ch3 独有，最系统）
四种渐进格式，权衡"简单 vs 表达力"：
1. **Simple Notes**：原子事实，O(1) 开销，但丢失关联，综合查询需靠启发式拼凑。
2. **Enhanced Notes**：完整叙事段落，语义完整，但冗余、难更新、越长越难嵌入。
3. **JSON Cards**：三层嵌套结构（类别→子类别→键值），支持部分更新，但刚性强、无法表达多维信息。
4. **Advanced JSON Cards**：加 backstory（为何存）、person/relationship（为谁存）、时间戳，解决同名实体消歧；代价是生成维护成本高。

实践选择：关键且少量→Advanced JSON Cards；大量非关键→Simple Notes；生产多用混合。  
前沿形态（ch3）：User as Code——记忆存为可执行代码（dataclass + 检查函数），聚合统计/冲突发现/约束执行从 LLM 心算变为确定性代码（聚合题正确率 6–43% → ~99%）；User as Engram——把事实写进模型哈希槽位；参数化多模态记忆——感知向量直接挂载模型。  
框架案例（ch3）：Mem0 两阶段流水线"提取→对比→决策"（ADD/UPDATE/DELETE/NOOP），图记忆变体 Mem0-g；Memobase 用户画像（Profile 槽位）+ 事件记忆（时间线），缓冲批量提取降成本。


# 五、记忆评估（ch3 独有）
- 公开基准：LoCoMo（300 轮/35 会话级超长对话，问答+摘要+多模态三类任务）。
- 八项能力归纳（个人信息、偏好追踪、上下文切换、记忆更新、多会话连续性、复杂思考、时间感知、冲突解决）。
- 三层次框架：① 基础回忆（单条精确事实存取）② 多会话检索（跨会话关联推理）③ 主动服务（发现隐藏关联、主动预警，如护照过期提醒）。后文以 RAG 技术逐层提升此框架。


# 六、RAG 核心流程与分块
- 流程共识：检索相关片段 → 注入上下文 → LLM 生成。ch8 补充发展阶段：朴素 RAG（BM25，2020–21）→ 高级 RAG（稠密嵌入+重排，2022–23）→ 模块化 RAG（混合检索/MQE/HyDE，2023–至今）。
- 分块：三策略（ch3）——固定大小（512 token，重叠 50–100）、递归/结构感知（生产默认；ch8 落地方案：MarkItDown 统一转 Markdown 后按标题层次分割 + token 估算含中英文）+ 语义切分（ch3，按嵌入相似度断崖）。默认起点 256–1024 token、重叠 10–20%。固有缺陷：切断上下文（代词/时间/实体指代丢失）。


# 七、检索技术（两文互补，合并）
- 稠密嵌入：Word2Vec → BERT/BGE-M3（上下文感知、一词多义）；余弦相似度衡量；ANN 索引（ANNOY 树形、不支持增量 vs HNSW 图形、支持增量，动态库选 HNSW）。
- 稀疏嵌入：TF-IDF → BM25（词频饱和 k1 + 长度归一化 b）→ 学习型 SPLADE/BGE-M3 稀疏分支。擅长精确匹配（代码、人名），不懂同义。
- 混合检索：稠密+稀疏并行 → RRF 或归一化加权融合 → 神经重排序（cross-encoder，如 bge-reranker-v2-m3，对候选池前 50 精排）。指标：recall@k（注意 ch3 指出书中口径实为 hit rate，1−recall@20 即"检索失败率"）、MRR、nDCG。
- 高级策略（ch8 独有）：MQE 多查询扩展（LLM 生成语义等价查询，提高召回）；HyDE 假设文档嵌入（先 LLM 生成假设答案再检索，弥合问题/文档语义鸿沟）；统一"扩展-检索-合并"框架（候选池乘数默认 4）。建议：一般查询 MQE，专业领域 MQE+HyDE，性能敏感仅基础检索。


# 八、知识组织与 RAG 进阶（ch3 独有）
- 结构化索引：RAPTOR 树状递归摘要（概念→细节下钻）与 GraphRAG 实体-关系图（多跳推理、实体消歧强项；局限：三元组化导致语义降级、依赖 LLM 提取准确率）。判断标准：跨文档综合/多层次导航才值得；混合检索已覆盖多数场景。
- 上下文感知检索（Anthropic）：索引前用 LLM 给每个分块补上下文前缀再嵌入，同时增强稀疏与稠密检索。经官方博客核实，数字准确：检索失败率降 49%（5.7%→2.9%），加重排降 67%（5.7%→1.9%）；成本靠 prompt caching 摊薄。注意与"上下文感知压缩"（运行期裁剪对话）区分：一加一减。
- 智能体化 RAG：检索封装为工具，Agent 按"思考→行动→观察"多轮迭代探索；简单查询非智能体化更快，复杂多跳查询显著胜出。安全：防间接提示注入/知识库投毒（指令-数据分离、高风险动作不凭检索内容触发）。
- 治理：增量更新（选 HNSW）、失效内容版本/时间过滤、多租户检索层权限隔离。
- OpenViking 文件系统范式：URI 目录 + L0/L1/L2 摘要按需加载。
- 多模态摄取：原生多模态（ViT 统一语义空间）/提取为文本（OCR）/工具化分析（按需深入）三选。
- 结构化数据知识发现：LLM 提取案例为结构化因子 → 聚类构建因子重要性模型（如司法量刑）→ 对话式引导收集信息。


# 九、记忆 × RAG 融合（两文汇合点）
ch3 实验证实：把对话历史当知识库做 RAG，提升第二层"多会话检索"（两辆车预约案例需多轮检索），但矛盾指令（转账金额反复修改）与第三层主动服务（机票×护照过期）仅靠分块检索不够。ch8 工程上同样将 RAG 与记忆作为双工具（memory_tool + rag_tool）组合进问答助手。
结论——双层记忆架构：Advanced JSON Cards 常驻上下文提供"概览"（结构化核心事实），上下文感知检索按需召回原始对话"细节"（带人物/时间/意图前缀解决冲突裁决），两者叠加才落地最高层"主动服务"。ch8 的语义记忆实现与之呼应：Qdrant 向量 + Neo4j 图混合（向量检索 0.7 + 图检索 0.3 加权），与 2026 年行业"混合向量-图存储为复杂场景推荐"的共识一致。


# 十、冲突裁决说明
- 记忆分类差异（ch3 含程序记忆、ch8 含感知记忆）：非矛盾，经核实 2026 年行业主流为 working/episodic/semantic/procedural 四层（Tulving 框架），感知记忆为多模态扩展，故并集保留。
- Anthropic 上下文检索数据：49%/67% 与官方博客原文一致，保留。
- 其余（工作记忆 7±2、BERT 512 token 上限、HNSW 增量特性、LoCoMo/Mem0 引用、RAG 三阶段演进）均经核实准确或互相兼容，无删除项。
一句话：记忆解决"跨会话记住用户"，RAG 解决"按需取回知识"，最终合流为"结构化常驻 + 检索增强"的双层架构——概览给视野，检索给细节，二者缺一不可。
